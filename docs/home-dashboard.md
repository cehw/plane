# Plane 首页摘要

## 页面与数据职责

首页先展示按旧工作台设定分组的日期横条，随后展示四个重点项目的当前状态与下一步，再展示采集和 NAS 摘要；完整待办可展开查看。未完成项目优先，依次按逾期、Plane 原生任务优先级、进行中、截止日期和最近工作记录排序；不根据历史描述猜测重要性。项目卡分别链接原生看板、时间轴和下一步任务详情，长项目清单折叠保留。国家覆盖地图、资产存储和完整性在数据资产默认总览页同一区域展示，Hub 总首页只保留运行摘要、项目进度和待办。备份与恢复页保留完整备份回执。

当前任务来自 Plane 数据库，过滤当前用户可见项目及已归档/草稿条目。历史“已做”记录已作为带来源、日期和“历史成果”标签的已完成事项迁入原生看板；历史“进行中”不直接视为当前运行状态。

`GET /api/workspaces/<slug>/hub-summary/` 要求已有 Plane 登录，以及工作区管理员或成员身份。每个工作区只读取自己的 `<slug>.json`。缺少快照时显示等待状态，不伪造零值或正常状态。

## 本机摘要同步

既有工作看台 `scripts/data-status-client.mjs` 支持可选 `hubSnapshotPath`。调用方通过隐藏 stdin 提供已有 Sites 凭据、`operation=sync` 和私有输出文件路径；客户端只读导出 Climet3 状态、更新 Sites 后读回，读取工作记录，将聚合摘要原子替换到本地文件。该文件不得加入 Git。挂载整个摘要目录至 API 容器 `/code/hub-data`，只读；文件名使用实际工作区 slug。

快照包含 `snapshot`（已有 Netatmo 摘要）、`work_records`（id、项目、标题、种类和日期）、`work_records_updated_at` 和 `workdesk_url`。没有原始观测、站点 ID、采集凭据或 Sites token。

网页每分钟读取已同步状态。采集状态超过 90 分钟未同步则标过期；最近观测超过 60 分钟标延迟；最近 NAS 成功回执超过 90 分钟标延迟，最近失败单独展示。同步任务仍在 Windows Codex 本机运行，离线时保留最近快照并显示其时间。

## 构建和运行

基于上游 `v1.4.3`。在仓库根目录使用 Docker：

```sh
docker build -t plane-hub/web-deps:v1.4.3 -f deployments/hub/Dockerfile.web-deps .
docker build -t plane-hub/web:v1.4.3-hub1 -f deployments/hub/Dockerfile.web-hub .
docker build -t plane-hub/api:v1.4.3-hub1 -f deployments/hub/Dockerfile.api-hub .
```

Windows Git 检出会把上游 i18n 符号链接存为文本，web 构建文件在 Linux 内恢复该链接，保证原生语言资源被打包。

web 镜像替换前端静态资源；API 镜像在官方后端上新增摘要接口。无需数据库迁移。使用现有 Compose 的本地覆盖配置指定上述 web / api 镜像及摘要目录挂载，其他服务沿用发布配置。具体本机入口、目录和回退配置见不公开的 `local-hub.md`。

## 验证

- 十一项前端单元测试：过期源状态、最新备份失败、观测延迟、缺失快照、正常状态、历史记录顺序与语义。
- 五项后端单元测试：缺失/损坏快照、工作区文件隔离、匿名请求、已登录非成员。
- 实际工作区只读集成检查、前端构建、TypeScript 检查和新增代码 OxLint。
- 浏览器已验证登录后的真实指标、原生菜单语言、768px 窄屏布局与刷新按钮。

## 原生模块对应

项目和当前任务使用 Projects / Work items，说明和工作日志使用 Pages。全球观测与 NAS 监控使用本次原生首页摘要组件。原工作台历史记录已按项目迁入私有 Pages，保留原日期、来源、记录类型与记录 ID。当前项目摘要以 Plane 项目说明为准，下一步及任务状态以 Plane Work items 为准；旧工作时间轴作为历史来源副本保留，不双向覆盖任务状态。

## 任务进度与待办

使用 Plane 活动任务查询器排除草稿、归档与收件箱条目。完成率为已完成除以未完成加已完成，取消任务不计入；没有有效任务时显示暂无任务。待办按逾期、原生优先级、进行中、截止日（空日期在后）排序，再以创建时间和 ID 稳定排序。首页新建按钮打开 Plane 原生任务表单，创建后刷新；点击条目进入原生详情更新状态。

验证包含空任务和完成率单元测试，以及自动回滚的数据库检查：完成、进行中、取消、草稿、归档、逾期统计与待办排序；未保留测试任务。

## 项目迁移后的首页

首页直接读取所有可见项目的原生说明与首项未完成工作项，保留证据截至日期。完整历史进展保留于 Pages；其中明确“已做”的成果也迁入已完成列。完成率统计已录入事项，包含这些历史成果，不代表科研项目整体完成度。不明确的旧运行/提交状态保留“待核实”标签。项目说明可在原生设置中维护，下一步随 Work items 状态变化更新。

采集与备份卡用状态点和 UTC+8 最近事件时间显示，绿色代表快照仍有效且相应时效正常；延迟、失败或过期时保留事件时间并展示原因。

重点项目卡可直接打开原生项目任务，并显示当前状态与首项下一步；全部项目入口保留。首页不再将任务完成比例画作原工作台的进度条。

## 原生四列看板

既有项目的原生 Work items 默认采用 Kanban，按待办、进行中、等待反馈、已完成排列，显示空列。布局持久化到现有用户的 ProjectUserProperty，同一账户跨设备复用。确认没有任何关联任务后，通过原生接口软删除旧空状态（Backlog、Cancelled、待核实），仅保留四个状态，不依赖过滤器隐藏列。等待反馈属于 Plane started 状态组，但首页将其单独统计，避免误计为正在推进。

首页进度卡和项目行“打开看板”直接进入原生项目看板视图。拖动卡片即可修改原生状态；首页每分钟重新读取。迁移的历史完成项使用来源记录 ID 去重，保留原日期，不把导入时间当作历史完成时间，也不虚构截止日期。


## 原生时间轴与数据资产

首页项目选择器可直接进入同一项目的原生看板或时间轴，详情顶部可切换项目、布局并返回 Hub。当前社区版本的时间轴按项目展示，不是跨项目总甘特图。22 个项目各保存一个私有 Kanban 和一个 Gantt 视图，布局值分别为 `kanban`、`gantt_chart`，原生工作项是唯一任务来源；没有另写甘特图或添加依赖箭头。

57 项历史已完成事项的开始/结束日逐项采用原工作记录日期；2 项本次已完成建设事项采用记录中的 2026-11-01，共 59 项有日期。17 项当前未完成事项没有确定排期，两个日期字段保持空白。单日历史记录不代表全天工时，历史结束日不作为新截止承诺。其余历史进行中/计划记录保留在 Pages，不自动变成当前运行状态或补造日期。

数据资产的主要入口为 `/<workspaceSlug>/data/`，使用 Plane 的 Header、Breadcrumbs、Card、Badge、Tabs、Table 和 Button。数据总览、备份与恢复两个标签页展示同一份只读状态；地图使用 Leaflet 多级底图与真实站点聚类，外层沿用 Plane 组件。Plane 本身没有 Netatmo/NAS 专用内置模块，因此数据查询和指标解释是本地集成。

本地私有快照增加源站经纬度、分类和最近观测时间，不含站点 ID 或气象原始观测。同步仍先向 Sites 写入聚合格网与国家汇总、读回验证；精确位置在发送前剥离，只合入本地 Plane JSON。工作区成员权限继续保护该接口。旧 Sites 页面作为历史来源副本保留；首页主要入口和快捷链接使用 Plane 内部页面。

本次验证：11 项前端测试、TypeScript、OxLint、生产构建；逐项日期核对、17 项空日期保留、44 个私有视图的授权读取、汇总与聚合数据读回。数据库迁移前后使用现有管理数据备份脚本保存可恢复副本。


## 社区版维护方式

本 fork 固定基于免费 AGPL-3.0 社区版，保留上游许可证和版权声明。侧栏版本标识只展示版本；套餐比较、订阅入口、Pro 徽标与批量操作推广横幅不展示。旧 billing 地址只显示社区版信息；未实现的跨项目 Cycles 总览说明当前限制并引导至项目。

Hub 扩展在 `codex/home-summary` 分支维护，发布源码时排除 `_tmp/`、数据库、快照、备份、真实运行环境配置与本机私有部署记录。上游下载的 `upstream-variables.env` 是未填写实例凭据的示例配置，不是运行中的 `plane.env`。


## 重点项目与按洲覆盖

项目卡状态由全部未完成事项汇总，下一步采用同一任务排序，不会因较早创建的普通待办掩盖紧急任务。优先级直接读取原生任务；未设置时明确显示未设优先级，不自动写入或修改。已录入事项完成不表示整个研究项目完成，缺少日期仍保留空值。

数据资产默认总览页使用 `HubCoverage`，地图不放在 Hub 总首页。国家/地区以中文名称和源代码显示，按大洲折叠并汇总近 24 小时站点；支持名称、代码及大洲搜索。默认排除只有旧参考记录的地区，可勾选显示全部已见地区。近期站点 = 两者都有 + 近期新增，去重并集额外含旧集独有。没有快照、缺失字段与过期状态不冒充零值或正常。

地理映射来自 [UN M49](https://unstats.un.org/unsd/methodology/m49/)，提取于 2026-11-01，以系统 ISO 区域表将 alpha3 转为 alpha2；美洲按南美洲及北美洲（含中美洲、加勒比）展示，另显南极洲。TW、XK 为源代码显示补充，未知代码保留未归类，跨洲地区按统计分组仅出现一次。它是展示分组，不表示全球覆盖率或地理边界判断；国家/地区数来自最新快照，不硬编码 131。


## NAS 容量口径

数据资产 NAS 卡片环形图及 Hub 首页简要进度条使用 DSM 共享文件夹配额，显示已用、总额、剩余及独立的 DSM 核对时间。共享配额是人工读取的记录，超过 24 小时提示重新核对，不能用同步时间冒充新读数。缺失值显示等待核对，不显示虚假的 0%。私有配额记录与运行快照均不进入 Git。

数据总览及备份页另列 NAS 卷整体容量进度条：只读 SFTP 文件系统容量随既有状态同步更新，单位 TiB；它不是该共享的 20 TB 配额，也不是历史 CSV 大小。读取失败时保留旧容量及原时间并显示错误，超过 90 分钟标为待更新。

本次容量与布局验证：19 项前端单元测试、6 项导出与合并测试通过；TypeScript、OxLint 与生产构建通过。浏览器确认 Hub 总首页无地图，数据资产默认总览包含地图、按洲覆盖、完整性与容量；同步读回确认 hub_saved=true，配额原始核对时间独立保留。


## 在线采集分区

Hub 与数据资产使用同一在线采集组件：Netatmo 全球观测、HKO 站点观测、HKO 天气/预报核心产品、HKO 网站归档、Open-Meteo 实时/15 分钟产品/每日七天预报/每周历史补采共八条已发现的定时采集流集中展示。HRES 单独标记未接入监控，不编造下载状态；模型推理与 NAS 备份不计为采集。

每项显示状态点、最近采集时间（Netatmo 使用最近观测）、周期与异常；HKO 检查完成回执，其他任务检查已保存输出。部分城市或核心产品缺失显示警告，抓取了旧观测仍会提示观测延迟。空警告/提示属于 HKO 合法无事件状态，核心产品监控不代表警告接口的完整性证明。每天/每周任务按自身更新窗口判断，不套用十分钟阈值。只读定时表用于确认调度仍启用；采集摘要超过 90 分钟未核查不显示绿色。

采集延迟与源观测延迟在 checked_at 核查时刻判断，避免小时级看台同步间隔被误报为十分钟采集器停采；页面明确显示核查时间，超过 90 分钟未核查改为状态待更新。

本次在线采集验证：24 项前端单元测试、7 项 Python 导出测试、4 项摘要合并测试通过；TypeScript 与 OxLint 通过。只读现场核查获得七条附加采集流的周期、结果与时间，Sites 写入读回和本地快照均成功，未修改采集或备份任务。

## Netatmo 地图缩放

数据资产页使用本地打包的 Leaflet 1.9.4（BSD-2-Clause，许可证保留于 public/vendor/leaflet），底图按当前视口请求 OpenStreetMap HTTPS 瓦片；保留可见署名、浏览器默认缓存和 Referer，不预取或批量下载瓦片。实现参照 https://leafletjs.com/reference.html 与 https://operations.osmfoundation.org/policies/tiles/ 。

默认开启滚轮缩放；放大时加载更详细的地名与道路。真实坐标来自 Climet3 保存的 Netatmo 源站经纬度，最近 24 小时按 station_id 去重并采用最新观测的位置；旧参考集可选加入。点位不抖动、不按格网中心替代，不将其标称为实测 GPS 精度。

采用 [Supercluster 8.0.1](https://github.com/mapbox/supercluster/tree/v8.0.1) 与 KDBush 4.0.2（ISC，许可证与代码存于 public/vendor）；仅把 Supercluster 的裸导入改为本地相对路径。缩小时以带数量的圆环聚类表示分布，颜色比例表示旧参考独有/两者共有/相对参考新增，放大自动拆分到单站。点击聚类跳到下一拆分级别，点击单站查看位置及最近观测时间。最高缩放仍重合的站点保留数量，不伪造分离坐标。地图最多缩放到 19；聚类只是显示汇总，不影响去重数量。

研究过 [Leaflet.markercluster](https://github.com/Leaflet/Leaflet.markercluster)、[Leaflet.heat](https://github.com/Leaflet/Leaflet.heat)、[deck.gl](https://github.com/visgl/deck.gl)。本次选择 Supercluster 的视口查询与逐级展开，避免一次创建数万 DOM 标记；未加入热力层，圆环不会暗示温度、雨量等数值。默认仅近期站点，按钮可加入旧参考集，灰色不代表当前在线。索引仅在点位快照时间或筛选改变时重建，周期刷新保留视口。

测试覆盖坐标和时间不变、默认排除历史站点、各级聚类分类计数守恒、同位置多站不丢失、滚轮默认开启；同步测试确认精确坐标不会进入 Sites 请求且只读刷新不改写点位原时间。

## 暖白外观

首页、数据资产顶部和个人偏好提供同一外观选择器：暖白、浅色、深色、跟随系统。暖白复用原生 custom 用户主题（品牌色 #2864b4，背景 #faf8f3，light palette），并使用明确的暖灰中性色阶和透明叠层，保留卡片、边框、文字和状态色层级。只在完整预设匹配时应用，不改写其他自定义主题。主题保存到现有用户 profile，同一账户在其他设备重新载入后读取；不是仅保存在本机的 CSS 开关。切换等待账户保存成功后刷新，失败显示提示。无需修改采集、备份或数据库结构。

暖白验证：两个单元测试覆盖预设识别、其他主题保留，以及正文/次级/辅助文字在暖白色阶上的对比度；TypeScript、OxLint 和生产构建通过。浏览器实测深色→暖白→深色→暖白保存与重载，首页、原生看板、数据资产均使用暖白；外观控件实际背景为 rgb(250,248,243)。

## HKO 分组

在线采集将 HKO 归为一个分组，下分站点实测和天气预报产品，分别读取各自回执显示采集时间、状态、周期；首页沿用紧凑双来源，数据资产展开覆盖详情。网站归档放在分组内附属折叠项，不另计站点，异常时自动展开。所有采集器仍独立运行。

实测列出七类变量的站点数、源观测时间与标准站名；产品列出实况站点/行政区、海温、土温深度、本地及九天预报、提示与警告的本次文件可用情况。温湿度表展示双方数量、交集、去重并集；不相加变量、来源、深度和行政区。标准站名只合并明确别名 HK Park → Hong Kong Park，未确认同站的近似地名仍分开。名称集合不是物理仪器总数，两套源观测时间不被抓取时间覆盖。

天文台说明机场内可能使用不同风观测设施，不能由区域名直接推断同一仪器：[区域天气说明](https://www.hko.gov.hk/en/wxinfo/awsgis/regional_portal.html)。覆盖元数据来自本地只读导出，经既有私有快照进入 Plane，缺少覆盖元数据时显示等待同步。

HKO 分组默认折叠，标题区保留两类来源的状态与最近采集时间；点击标题展开数量、站名和覆盖比较。附属网站归档异常也在收起时提示。


## 页面布局与审阅范围

首页以按工作线分组的真实日期横条为首要内容，随后显示重点项目状态与下一步，再展示在线采集和 NAS 概要；待办、完整项目清单和历史记录保留在可展开区域。首页和数据资产使用相同的最大内容宽度（1440px），窄屏自动改为单列。

| --- | --- |

## 原工作台日期横条迁移

首页横条沿用旧工作台的含义：按真实开始/结束日期定位，蓝色已做、橙色进行中、紫色计划、绿色汇报；历史类型只说明当时记录，不作为当前运行状态。单日横条不表示全天工时，空白日期保持空白，未定日期事项单独列出，不推算完成百分比。

分类沿用科研（Ongoing、Revision、研究支持、学术事务）、Stellerus、Personal 和待归类；Stellerus 用原 `siteScope` 按场区/业务项目归组，同一条记录仅出现于一条工作线。收起分类或工作线时仍保留各条记录的真实色段，展开查看明细。展示复用 Plane 原生 Gantt 的日期轴、滚动、今天线与组件风格；分组包络仅用于坐标布局，不保存为项目排期，也不填满没有记录的日期。

历史记录从现有私有摘要读取；同步保留 `siteScope`，不把私有记录加入公开源码。API 仅返回可见项目的历史，利用已迁移原记录 ID 链接原生已完成事项或历史 Page。当前原生事项保持独立维护；已关联历史条目按 ID 去重。首页重点项目区保留当前状态和下一步，撤回另行添加的事项百分比条。

本次验证：8 项日期/分组/去重/空白区间/链接测试、13 项重点项目与状态测试、9 项后端测试通过；实际只读接口核对 65 条原记录、11 条场区字段、57 个原生事项链接及 22 个历史页，17 项未定日期待办保留。原记录与另有日期的原生事项去重后共 67 条。TypeScript、OxLint、生产构建通过；桌面浏览器验证分组开合、周/月切换、同日记录列表、Issue/Page 跳转。未检查手机版。


## 科研项目统一管理

原生 Projects 与首页时间轴复用同一份工作线分类，项目仍以 Plane 的唯一项目 ID 管理。Projects 提供全部、科研、Stellerus、Personal、其他分类，科研按 Ongoing、Revision、研究支持、学术事务展示；`?scope=research` 可直接进入科研分类。搜索、原生筛选及排序继续生效，分类数量反映筛选后的项目。

项目卡保留原生项目说明，并从已有登录态摘要读取当前状态、未完成数、下一步和原生看板/时间轴入口。历史总结链接指向同一项目已迁移的 Page，保留证据日期；未记录下一步时明确显示空状态，历史完成事项不代表整个科研项目完成。首页时间轴提供科研管理入口，单项目工作线旁可直接进入其看板。

本次复用已存在的 13 个科研项目、45 条历史记录及其原生历史页，没有重复建项目、复制事项或改动日期。展示每分钟刷新原生事项摘要；新项目未归类时归入其他。

验证：10 项分类与时间轴测试、TypeScript、OxLint 和生产构建通过。桌面读回确认科研 13 个项目、9 项未完成（其中 1 项等待反馈）；首页分类入口、原生看板/时间轴/历史页链接可用，未检查手机版。共享分类抽取后，含跨文件 TypeScript 导入的测试使用仓库现有 tsx 执行器，例如构建容器内 `/app/packages/i18n/node_modules/.bin/tsx --test core/components/project/__tests__/project-scopes.test.mjs core/components/home/__tests__/hub-home-timeline.test.mjs`（工作目录 `apps/web`）。
