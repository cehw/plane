# Plane 首页摘要

## 页面与数据职责

首页优先展示采集状态、NAS 备份、进行中任务和逾期待处理。国家数量、站点规模与归档容量留在数据详情页。状态卡下方直接展示四个近期项目的任务进度条：进行中的项目优先，其余按最近工作记录排序；无有效任务的项目不占位。随后展示项目进展表、按截止日排序的前八项待办、近期记录及需要关注的缺口。沿用 Plane 主题、图标、登录和工作区权限；没有嵌入外部 HTML 或在浏览器保存服务密钥。

当前任务来自 Plane 数据库，过滤当前用户可见项目及已归档/草稿条目。历史“已做”记录已作为带来源、日期和“历史成果”标签的已完成事项迁入原生看板；历史“进行中”不直接视为当前运行状态。

`GET /api/workspaces/<slug>/hub-summary/` 要求已有 Plane 登录，以及工作区管理员或成员身份。每个工作区只读取自己的 `<slug>.json`。缺少快照时显示等待状态，不伪造零值或正常状态。

## 本机摘要同步

既有工作看台 `scripts/data-status-client.mjs` 支持可选 `hubSnapshotPath`。调用方通过隐藏 stdin 提供已有 Sites 凭据、`operation=sync` 和私有输出文件路径；客户端只读导出 Climet3 状态、更新 Sites 后读回，读取工作记录，将聚合摘要原子替换到本地文件。该文件不得加入 Git。挂载整个摘要目录至 API 容器 `/code/hub-data`，只读；文件名使用实际工作区 slug。

快照包含 `snapshot`（已有 Netatmo 摘要）、`work_records`（id、项目、标题、种类和日期）、`work_records_updated_at` 和 `workdesk_url`。没有原始观测、站点 ID、采集凭据或 Sites token。

网页每分钟读取已同步状态。采集状态超过 90 分钟未同步则标过期；最近观测超过 60 分钟标延迟；最近 NAS 成功回执超过 90 分钟标延迟，最近失败单独展示。同步任务仍在 Windows Codex 本机运行，离线时保留最近快照并显示其时间。

## 构建和运行

基于上游 `v1.4.3`。在仓库根目录使用 Docker：

```sh
docker build -t plane-hub/web-deps:v1.4.3 -f deployments/hub/Dockerfile.web-deps .
docker build -t plane-hub/web:v1.4.3-hub1 -f deployments/hub/Dockerfile.web-hub .
docker build -t plane-hub/api:v1.4.3-hub1 -f deployments/hub/Dockerfile.api-hub .
```

Windows Git 检出会把上游 i18n 符号链接存为文本，web 构建文件在 Linux 内恢复该链接，保证原生语言资源被打包。

web 镜像替换前端静态资源；API 镜像在官方后端上新增摘要接口。无需数据库迁移。使用现有 Compose 的本地覆盖配置指定上述 web / api 镜像及摘要目录挂载，其他服务沿用发布配置。具体本机入口、目录和回退配置见不公开的 `local-hub.md`。

## 验证

- 十一项前端单元测试：过期源状态、最新备份失败、观测延迟、缺失快照、正常状态、历史记录顺序与语义。
- 五项后端单元测试：缺失/损坏快照、工作区文件隔离、匿名请求、已登录非成员。
- 实际工作区只读集成检查、前端构建、TypeScript 检查和新增代码 OxLint。
- 浏览器已验证登录后的真实指标、原生菜单语言、768px 窄屏布局与刷新按钮。

## 原生模块对应

项目和当前任务使用 Projects / Work items，说明和工作日志使用 Pages。全球观测与 NAS 监控使用本次原生首页摘要组件。原工作台历史记录已按项目迁入私有 Pages，保留原日期、来源、记录类型与记录 ID。当前项目摘要以 Plane 项目说明为准，下一步及任务状态以 Plane Work items 为准；旧工作时间轴作为历史来源副本保留，不双向覆盖任务状态。

## 任务进度与待办

使用 Plane 活动任务查询器排除草稿、归档与收件箱条目。完成率为已完成除以未完成加已完成，取消任务不计入；没有有效任务时显示暂无任务。待办按截止日升序、无日期在后，再按创建时间稳定排序。首页新建按钮打开 Plane 原生任务表单，创建后刷新；点击条目进入原生详情更新状态。

验证包含空任务和完成率单元测试，以及自动回滚的数据库检查：完成、进行中、取消、草稿、归档、逾期统计与待办排序；未保留测试任务。

## 项目迁移后的首页

首页直接读取所有可见项目的原生说明与首项未完成工作项，保留证据截至日期。完整历史进展保留于 Pages；其中明确“已做”的成果也迁入已完成列。完成率统计已录入事项，包含这些历史成果，不代表科研项目整体完成度。不明确的旧运行/提交状态保留“待核实”标签。项目说明可在原生设置中维护，下一步随 Work items 状态变化更新。

采集与备份卡用状态点和 UTC+8 最近事件时间显示，绿色代表快照仍有效且相应时效正常；延迟、失败或过期时保留事件时间并展示原因。

近期项目进度卡可直接打开原生项目任务，并显示首项下一步；全部项目入口保留。进度条只表示已录入 Plane 的任务完成比例，不代表科研项目整体完成比例。

## 原生四列看板

既有项目的原生 Work items 默认采用 Kanban，按待办、进行中、等待反馈、已完成排列，显示空列。布局持久化到现有用户的 ProjectUserProperty，同一账户跨设备复用。确认没有任何关联任务后，通过原生接口软删除旧空状态（Backlog、Cancelled、待核实），仅保留四个状态，不依赖过滤器隐藏列。等待反馈属于 Plane started 状态组，但首页将其单独统计，避免误计为正在推进。

首页进度卡和项目行“打开看板”直接进入原生项目看板视图。拖动卡片即可修改原生状态；首页每分钟重新读取。迁移的历史完成项使用来源记录 ID 去重，保留原日期，不把导入时间当作历史完成时间，也不虚构截止日期。


## 原生时间轴与数据资产

首页项目选择器可直接进入同一项目的原生看板或时间轴，详情顶部可切换项目、布局并返回 Hub。当前社区版本的时间轴按项目展示，不是跨项目总甘特图。22 个项目各保存一个私有 Kanban 和一个 Gantt 视图，布局值分别为 `kanban`、`gantt_chart`，原生工作项是唯一任务来源；没有另写甘特图或添加依赖箭头。

57 项历史已完成事项的开始/结束日逐项采用原工作记录日期；2 项本次已完成建设事项采用记录中的 2026-11-01，共 59 项有日期。17 项当前未完成事项没有确定排期，两个日期字段保持空白。单日历史记录不代表全天工时，历史结束日不作为新截止承诺。其余历史进行中/计划记录保留在 Pages，不自动变成当前运行状态或补造日期。

数据资产的主要入口为 `/<workspaceSlug>/data/`，使用 Plane 的 Header、Breadcrumbs、Card、Badge、Tabs、Table 和 Button。资产与完整性、站点覆盖、备份与恢复三个标签页展示同一份只读状态；地图复用既有 D3 聚合格网视图，外层沿用 Plane 组件。Plane 本身没有 Netatmo/NAS 专用内置模块，因此数据查询和指标解释是本地集成。

本地快照保留已存在的 0.5 度格网及国家汇总，未新增站点 ID 或原始观测。同步仍先更新既有 Sites、读回验证，再将同一份聚合内容写入私有本地 JSON；这一调整只扩大本地展示字段，不改变对外传输内容。旧 Sites 页面作为历史来源副本保留；首页主要入口和快捷链接使用 Plane 内部页面。

本次验证：11 项前端测试、TypeScript、OxLint、生产构建；逐项日期核对、17 项空日期保留、44 个私有视图的授权读取、汇总与聚合数据读回。数据库迁移前后使用现有管理数据备份脚本保存可恢复副本。
